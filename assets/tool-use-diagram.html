The hidden risk: prompt injection. If a tool returns untrusted text (a web page, an email, a document), that text can carry instructions the model may follow. A tool result is data, never instructions — but models don't always honor that boundary. Treat tool output as hostile input, and never interpolate it into SQL, shell, or eval().

✅ Use tools when

  • You need live data (weather, DB, stock)
  • The action has side effects
  • You need determinism (math, dates)
  • The result must be authoritative
  • You want an audit trail

❌ Don't use tools when

  • A plain prompt already answers it
  • A bad call is irreversible (no undo)
  • You have no validation layer
  • 40 overlapping tools confuse the model
  • The task is pure reasoning

🔒 The security rules (non-negotiable)

  1. Validate every argument — types, ranges, allowlists
  2. Never interpolate model output into SQL / shell / eval
  3. Allowlist, don't blocklist — define what's allowed
  4. Separate read-only tools from side-effecting ones
  5. Treat tool results as hostile — they can carry injected instructions
  6. Cap the loop — always have a max iteration count
  7. Log every call (input + output) for audit
