Memory — three tiers
Memory is a retrieval problem, not a storage problem.
1 · Short-term
Conversation buffer — last N turns
Context windowfast · free · limited
2 · Working
Summary / scratchpad — compressed history
In the promptsurvives overflow
3 · Long-term
Vector store / database — facts, preferences
External storeretrieved on relevance
The hidden risk: memory pollution. Every stored fact becomes a future retrieval candidate. The failure mode isn't "forgot" — it's "remembered the wrong thing and used it confidently." A small, high-quality memory beats a large, noisy one.

✅ Use memory when

  • Conversations span sessions
  • Preferences must persist
  • Tasks exceed the context window
  • Personalization matters
  • Multi-day workflows

❌ Don't use memory when

  • Each request is stateless
  • You can't scope what to remember
  • Data is sensitive and unmanaged
  • Stale facts are worse than none
  • No retrieval evaluation
  • Session is short + single-purpose

⚠️ The five failure modes — test all before shipping

  1. Forgetting — the fact was never stored
  2. Wrong recall — a similar but incorrect memory surfaced
  3. Pollution — too many memories, signal lost
  4. Staleness — a superseded fact returned
  5. Leakage — user A's memory surfaced for user B
