The hidden risk: summarization loses the needle. Compress a conversation and you may drop the one detail the current question needs. Compression is lossy by definition — measure what you lose, don't assume it's fine.

✅ Engineer context when

  • Context is large
  • Quality is inconsistent
  • Near the window limit
  • Many tools compete for budget
  • Cost matters (length drives cost)

❌ Don't bother when

  • Context is tiny and quality is good
  • You haven't measured quality
  • Compensating for bad retrieval
  • You're just stuffing more in
  • The task needs all the detail
  • You can't tell what's being used

📐 The ordering rules

  1. Stable content first — enables prompt caching
  2. Reference material in the middle — retrieved docs, examples
  3. Recent history near the end — most relevant turns
  4. Current ask LAST — recency bias works for you
  5. Critical constraints repeated — start AND end for hard rules

The four levers, pulled in order: Rank → Dedupe → Compress → Truncate. Truncation is the last resort, not the first.
