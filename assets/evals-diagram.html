The hidden risk: the eval becomes the target. Optimize against a narrow test set and you get Goodhart's law — the metric improves, the product doesn't. Rotate cases, hold out a set, and add every production bug as a new case.

✅ Use evals when

  • Before every prompt/model change
  • Choosing between models
  • Quality is subjective
  • You have a regression history
  • Stakeholders need evidence

❌ Don't use evals when

  • You can't define "correct"
  • Test set is tiny + unrepresentative
  • A unit test would suffice
  • Same model judges itself
  • There's no gate
  • You're scoring vibes on 3 cases
